# 并行开发路线

第 1 阶段剩下的工作分成三条路线，三个工作区同时进行。每条路线按顺序做，每一步照常一个 PR。各步的详细内容见 [第 1 阶段的 PR 计划](phase-1-prs.md)。

## 路线 A：内核和会话（主线）

1. 内核写入路径（PR 7）：参与者、房间、只追加的事件，统一的写入和判定，实时推送。
2. 网页插件和客户会话（PR 8）：连接器接口、网页插件、访客识别，坐席的会话列表和会话页。
3. 联系人页面和消息搜索（PR 11）。

B、C 两条路线接入会话的那一步，要等这条路线的第 2 步合并。

## 路线 B：工单

先做不依赖会话的部分，工单可以先手动创建：

1. 团队的工作时间和 SLA 设置；工单类型和自定义字段的管理。
2. 工单：字段、状态流转、领取 / 指派 / 转接，SLA 到期提醒和自动关闭的定时任务。
3. 工作台：我的工单、待领取、@我，工单详情的右侧栏。
4. 等 A 的第 2 步合并后：消息归入工单，合并、拆分、移动消息（PR 9 剩下的部分）。

## 路线 C：翻译和平台

1. 模型调用：使用平台设置中的接口，带业务标签，记录用量和费用。
2. 翻译服务：识别语言和书写方式并翻译，回复前的译文和回译；先只提供接口和测试。
3. 术语表的管理。
4. 等 A 的第 2 步合并后：客户消息的译文、会话页切换原文和译文、回复框下的译文预览（PR 10 剩下的部分）。
5. 有空档时：Docker Compose 部署和安装文档；管理员端的邮件、文件存储、系统状态（PR 12 的一部分）。

## 协作约定

- 每条路线一个工作区，分支名分别以 `a-`、`b-`、`c-` 开头。
- 这些文件容易冲突，合并前先 rebase 到最新的 main：
  - `locales/zh-CN.yaml`
  - `internal/auth` 中的权限和角色
  - `cmd/agents-desk/http.go`、`seed.go`
  - `docs/phase-1-prs.md`
- 生成的代码（`packages/client`、`routeTree.gen.ts`）有冲突时不手动合并，rebase 后重新运行 `bun run generate`。
- 迁移文件各自新建，文件名带时间戳不会冲突；不修改别的路线的迁移。
- 升级 Tenon 只在路线 A 中做，另外两条 rebase 后跟上。
