# agents-desk 开发计划

- 状态：讨论稿
- 日期：2026-11-22

计划按阶段划分，每个阶段由若干计划项组成。每个计划项对应一个或几个 PR，这里只定它的目标、主要内容和依赖，具体做法在开发时确定。依赖列为空的计划项可以同时开始。

---

## 做法

- **每个 PR 合并后应用都能运行**，可以单独验收。
- **内核先行，尽早合并。** 第 1 阶段的公共依赖只有会话内核（K1）。它只包含各计划项都要用的模型和写入路径，其余功能放到各自的计划项中。
- **接口先行。** 前后端分开的计划项，先合并接口定义和种子数据，之后前端和后端同时开发。
- **阶段可以重叠。** 后面阶段中依赖已经满足的计划项可以提前开始，例如知识库的内容管理、Telegram 连接器。
- **已有的代码按新设计调整。** 现有的成员、角色、团队在第 1 阶段改造。
- **正式上线前，安全和兼容按够用来做。** 数据库迁移、接口、种子数据都直接修改，旧数据和旧接口保持兼容的工作留到正式上线之后。

## 已完成

计划开始前：管理员端和工作区；成员登录和切换工作区；个人资料；偏好设置（语言、时区）。

第 1 阶段：F1 布局、F2 界面多语言、F3 前端骨架、F4 实时推送、F7 按请求的内容安全策略；A0 对齐新设计、A1 角色、A2 团队收件箱、A3 在线状态、A4 工作时间；K1 会话内核；C1 聊天插件后端、C2 聊天插件前端；D1a 收件箱列表、D1b 会话操作、D2 收件箱前端；E1 指派；T1 翻译后端、T2 翻译前端。
