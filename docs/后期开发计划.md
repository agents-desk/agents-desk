## 研发约定

- **独立 Worktree 协作**：每个计划项对应一个或若干逻辑清晰的 PR，在独立 Git Worktree 开发；每次改动须先通过本地全套静态校验（`gofmt`、`go vet`、`go test -race ./...`、`bun test apps/widget/tests/`、`bun run typecheck`、`bun run check`、`migrate verify`）且 GitHub `ci/build` 与 `ci/check` 全绿后再 Squash 合并。
- **数据模型与接口先行**：涉及数据表调整时同步编写完备表/字段 `COMMENT` 与双向 Goose 迁移；Go 端定义接口模型、枚举与权限标签后运行 `bun run generate` 同步生成前端强类型客户端，再由前端并行接入页面。
- **底座复用原则**：凡已提供协议抽象、队列路由与审计能力的底座，后续计划项直接实现契约或挂载处理器，不在业务包中另造轮子。

## 阶段 1：知识库与 AI 员工配置中心（KB1–KB4、AI1–AI2）

目标：跑通工作区企业知识的摄入、切分、混合检索与隔离，实现 `agent.Retriever` 真实落地，并上线 AI 员工配置中心取代占用占位页。

| 编号 | 计划项 | 主要工程内容 | 前置依赖 | 验收标准 |
|---|---|---|---|---|
| `KB1` | 知识库存储模型与管理接口 | 新增知识集合/文档/切片表（`knowledge_bases`、`knowledge_documents`、`knowledge_chunks`），含 `visibility`（`external` / `internal`）、适用范围（AI / 助手 / 帮助中心）、状态与索引版本；实现文章与问答片段 CRUD、权限点与双语操作日志 | 无（基于已有 PostgreSQL 与权限目录） | 文章/片段可按 `visibility` 与 `tenant_id` 严密隔离读写并具备跨工作区单测 |
| `KB2` | 文档转换、网页抓取与切分流水线 | 实现队列解析任务：PDF、Word、PPT、Excel、CSV、HTML 转保留标题路径与页码的 Markdown；支持网页抓取与周期刷新（强制经过出站 SSRF `outbound` 防护）；按结构切分文本块并写入切片表 | `KB1` | 上传多格式测试文档能在后台正确产出带页码和标题路径的结构化切片 |
| `KB3` | 混合检索与 `agent.Retriever` 实现 | 接入 Qdrant（按 `tenant_id` 与多版本 `index_version` 隔离集合），调用 `llm.Embedding` 构建向量索引并支持向量换代时双写零停机切换；结合 PostgreSQL 关键词召回与 `llm.Rerank` 重排实现 `agent.Retriever` 并注入 `agent.Service` | `KB2` | `ai_auto` 外部对话检索仅返回 `external` 可见切片，`citations` 正常回写生成记录与前端展示 |
| `KB4` | 知识库工作区端前端 | 在 `apps/web` 一级导航新增知识库模块，提供文章、片段、网页与文档列表页、Markdown 编辑器、切片详情查看、索引状态追踪与可见性配置 | `KB1`、`KB2` | 成员可在工作区完整维护文章、上传文档并查看生成的切分片段与索引进度 |
| `AI1` | AI 员工提示词版本历史与范围扩展 | 扩展 `bots` 配置版本快照表（`bot_versions`），记录修改人、差异与版本号；支持为每个渠道/外部群绑定提示词版本与接待上线配置接口（放量开关、防抖、插话、转人工默认团队） | `KB1` | 每次更新 Bot 提示词自动留存历史版本，支持回滚；历史生成记录可追溯实际使用的 `prompt_version` |
| `AI2` | 工作区 AI 配置中心前端 | 替换 `apps/web/src/routes/$slug/ai.tsx` 占位逻辑并将 `flags.AIWorkspace` 切换为正式可用；实现 Bot 列表与详情编辑器、知识源勾选、工具与高风险审批清单配置、渠道自动接待开关与版本回滚面板 | `AI1`、`KB4` | 运营人员无需调用 API 即可在前端新建机器人、绑定知识库与渠道并在收件箱验证生效 |

## 阶段 2：侧栏 AI 助手、外部工具与评测分析（AI3–AI7）

目标：上线高可用的坐席侧栏助手、安全的 OpenAPI/MCP 工具接入平台以及“沙盒测试—批量回归—效能洞察”工程闭环。

| 编号 | 计划项 | 主要工程内容 | 前置依赖 | 验收标准 |
|---|---|---|---|---|
| `AI3` | 会话侧栏 AI 助手 | 基于 `chat.Runs` 新增成员私有问答、改写（润色/语气转换/纠错）、长会话摘要总结与工单草稿填充动作；替换 `apps/web/src/components/ai-placeholders.tsx` 并接入详情栏“AI 助手”页签与转工单弹窗；同时实现进线问题自动分类与属性建议任务 | `KB3` | 坐席在服务型会话、工单与聊天中均可调用 AI 助手并一键插入回复框或填充转工单草稿，结果对客户严格不可见 |
| `AI4` | 外部业务工具平台（OpenAPI / MCP） | 新增 `agent_tools` 表存储第三方 API Schema 或远程 MCP Server 配置（密钥使用 `crypt.Crypt` 加密，出站强制走 `outbound` SSRF 防护）；动态构建受 `ExecutionContext` 约束的工具（自动从上下文提取联系人或组织 ID 注入请求，禁止模型跨人传参）；动态注册入 `agent.Registry` 并在工具标高风险时接入现有审批工作流 | `AI1` | 工作区配置模拟业务查单/退款接口后，AI 能自动带入联系人身份查询并经高风险人工批准执行回写 |
| `AI5` | AI“问成员”协作流与收件箱专属分组 | 在 `generations` 与时间线扩展仅成员可见的 AI 提问交互卡片（`ai_question`），成员提交答案后触发 `Runs.Notify` 恢复生成；在 `conversation.List` 与收件箱左侧导航增加“待审批 / 待确认 / AI 处理中 / 已转人工”专用筛选分组 | `AI4` | AI 执行中途向坐席求助时会话挂起不发误导回复，坐席作答后自动生成正确对客答复 |
| `AI6` | AI 沙盒模拟、评测集与回归引擎 | 新增评测集与用例表（`eval_sets`、`eval_cases`、`eval_runs`），支持从真实差评/转人工会话一键转入评测集；实现非生产环境沙盒测试入口与基于任务队列的多版本/多模型批量并行回归评分及知识缺口聚类接口 | `AI3`、`KB3` | 运维改版提示词或知识后可在前端对历史评测集批量试跑并输出命中率与差异对比 |
| `AI7` | AI 效能深度报表与对外帮助中心 | 扩展 `internal/report/translation.go`（或新增 AI 效能接口），直接聚合 `conversation_rounds.resolution_type`、`handover_reason`、`ai_generation_count` 与 `generations.mode = 'draft'` 采纳率、审批等待耗时；同时在 `apps/site` 或工作区公开路由上线对外帮助中心页面（读取 `external` 且发布态知识文章） | `AI6`、`KB4` | “AI 与翻译”报表完整展现解决率与转人工归因分布；未登录客户可在帮助中心浏览公开文档 |

## 阶段 3：客服进阶治理与可视化自动化（CS1–CS5）

目标：满足复杂客服团队的时间考核、精准负载分配、自由自动化编排与语音处理需求。

| 编号 | 计划项 | 主要工程内容 | 前置依赖 | 验收标准 |
|---|---|---|---|---|
| `CS1` | 专业 SLA 策略引擎 | 新增 `sla_policies` 与 `conversation_sla_states`；依据 `internal/hours`（工作时间与特殊节假日）后台计算首次响应与解决截止时间（`due_at`）；收件箱增加“按 SLA 到期排序”选项与即将违约事件驱动触发器 | 已有 `internal/hours` | 跨休息时段的新来信其 SLA 截止时间精确剔除非工作时段并支持排序置顶与违约记录 |
| `CS2` | 负载分配、接待上限与协同视图 | 团队收件箱增加“按未关闭打开会话最少（`least_loaded`）”分配算法与成员并发接待上限设置；新增会话关注者表（`conversation_followers`）同步纳入实时推送对象与可读范围计算；管理权限下支持查看指定同事收件箱 | 已有 `team` 与 `assign` | 到达上限的坐席不再获得新分配会话；关注者收到时间线更新推送 |
| `CS3` | 可视化自动化编排开放 | 基于现有 `automation_rules` 引擎开放规则新建、编辑、排序、启用接口与条件 AST 校验证器；扩充条件因子（渠道、识别语言、组织、自定义属性、SLA 状态、关键词正则）与动作集合（转到指定 Bot 接待、自动分派、加标签、修改字段、外呼 Webhook）；建设可视化规则编辑页 | `CS1` | 管理员可在“指派与自动化”设置页配置多条件自定义路由规则并经异步测试验证触发动作 |
| `CS4` | 工单细状态与客户工单门户 | 支持在 4 个核心状态大类下定义细状态映射关系并同步工单流程校检；为已登录认证客户建设独立网页门户页面展示本账号及所属组织的全部历史工单与回复通道 | `已有工单（ticket）与组织模块` | 客户可在独立门户筛选工单细状态并回复推进内部排查流程 |
| `CS5` | 语音消息自动转写流水线 | 对接 `llm.Transcribe` 模型槽位，扩展时间线派生内容处理作业：检测到入站语音附件时后台自动转写文本、识别语言并触发下游翻译与全文搜索索引同步 | 已有 `llm.Transcribe` 与多媒体管线 | 网页或聊天机器人渠道收到语音消息后，时间线自动展示语音播放器及转写文本和译文 |

## 阶段 4：全渠道扩展与聊天增强（CH1–CH6）

目标：补齐高价值外部沟通触点、办公平台协同接入以及内部聊天生产效率工具。

| 编号 | 计划项 | 主要工程内容 | 前置依赖 | 验收标准 |
|---|---|---|---|---|
| `CH1` | 聊天置顶、免打扰与程序化群机器人 | 为 `chat_membership_intervals`（或关联状态表）增加成员个人对聊天的 `pinned_at` 与 `muted` 标记并同步未读/提示音抑制逻辑；支持为内部群生成带 API 令牌与 `@回调 Webhook`（走 `outbound` 安全网段校验）的群机器人并允许绑定内部 Bot | 已有 `kind = chat` 与 `bots` | 成员可将关键聊天置顶或静音；外部告警系统可通过机器人令牌自动向内部群推送并响应 `@指令` |
| `CH2` | 邮件渠道双向连接器 | 实现标准 SMTP / IMAP（或 Postmark/Resend Inbound Webhook）邮件渠道连接器：支持 HTML 安全清洗转文本、附件提取、`Message-ID` / `In-Reply-To` / `References` 邮件线索识别与单活跃服务会话归并及带引用头回复发信 | 已有 `channel` 与 `conversation` | 多轮往返邮件自动聚合至同一服务型会话时间线，坐席译文回复可作为回复邮件精准回到原邮件线程 |
| `CH3` | WhatsApp 渠道连接器 | 基于官方 WhatsApp Business Cloud API 实现 Webhook 校验（`X-Hub-Signature-256`）、媒体下载、已读回执，及超过 24 小时客服窗口后引导坐席选用预审模板消息触达客户 | 已有 `channel` 与多媒体机制 | 客户在 WhatsApp 的消息、图片与语音可双向稳定同步，超 24h 限制在界面上具备明确提醒与模板选择 |
| `CH4` | 钉钉、飞书、Slack 机器人连接器 | 复用 `wecom` / `telegram` 沉淀的 `extgroup` 路由、分布式锁租约（仅长连接型需要）与多域联系人模型，独立开发三个内部协同办公渠道连接器（互无依赖，可并行推进） | 已有 `extgroup` 与 `wecom` 模板 | 三个渠道在单聊机器人与群内 `@机器人` 场景下均能正常进入对应服务团队收件箱并将 AI 或成员回复准确送回原群 |
| `CH5` | 团队商务沟通链接与 Telegram Business | 支持由团队收件箱所有而非单成员持有的共享商务沟通短链；扩展 `tgaccount`（或 `telegram`）适配 Telegram Business 商家账号授权挂载 | 已有 `widget` 商链与 `tgaccount` | 团队共享商务短链发起的聊天进入指定团队协作视图并由团队成员共同跟进 |
| `CH6` | 外部群按线程 / 话题拆分会话 | 升级 `extgroup` 与 `conversation` 会话索引策略：针对支持 Thread / Topic 的渠道群，支持按配置选择“整群共享单活跃会话”或“按平台主题线程隔离活跃会话” | 已有 `extgroup` 与 `CH4` | 开启线程隔离模式的群中两个不同话题各自形成独立服务型会话互不交叉干扰 |

## 阶段 5：桌面端、跨语言语义检索与商业化（PL1–PL4）

目标：完成桌面终端覆盖、海量历史跨语种检索升级以及面向开源社区与云端商业化交付收口。

| 编号 | 计划项 | 主要工程内容 | 前置依赖 | 验收标准 |
|---|---|---|---|---|
| `PL1` | 工作区桌面端应用 | 使用框架脚手架新增原生桌面端工程并复用工作区前端打包资源：对接系统托盘、操作系统桌面通知、未读角标汇总同步、点击系统通知唤醒并定位到具体对话以及自动更新检查器 | 已有实时推送与 `CH1` 通知配置 | 桌面应用可独立安装运行并在系统后台及时弹出新来信提醒且一键跳转处理 |
| `PL2` | 跨语言语义历史会话搜索 | 在消息处理管道新增异步向量索引任务：使用 `llm.Embedding` 写入 Qdrant 会话消息语义索引，与 PostgreSQL `search` 关键词结果做混合排序 | `KB3` | 坐席使用中文关键词能精确检索到小语种客户过往未译全历史消息中的相关会话 |
| `PL3` | 多语扩展、文档与开源合规发行 | 补充更多界面语言译文文件（通过 `locales` 对称校验）；选定并声明项目开源协议（`LICENSE`）；完善多场景部署指南、镜像与 Docker Compose / systemd 升级文档 | 已有翻译骨架 | 新增语种完整渲染无缺失报错；零基础按安装文档可一次性拉起全套生产依赖与主二进制服务 |
| `PL4` | SaaS 商业化套餐配额与计费接入 | 新增套餐订阅与租户配额中心：基于工作区生效限制坐席上限、启用渠道数、知识文档大小及联系月度 AI 额度包，接入账单事件与周期结算通知 | 已有 `tenant` 与 `llm` 预算模型 | 超额行为收到清晰限制提醒，账单订阅状态变化实时刷新工作区能力授权 |
