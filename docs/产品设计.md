## 1. 产品概述与多端组成

agents-desk 是一个团队综合服务平台，以 AI 为核心、以聊天为基础，界面原生支持简体中文和英文。

系统采用单二进制交付（Go 后端与 TanStack Start 前端打包为单一可执行文件），提供四个浏览器前端应用及统一 API：

| 端 | 挂载路径 | 使用者 | 职责与核心能力 |
|---|---|---|---|
| 官网（`apps/site`） | `/` | 访问者 / 成员 | 品牌官网展示与工作台入口引导 |
| 工作区端（`apps/web`） | `/app/`（含 `/t/{slug}/`） | 工作区成员 | 登录与选择工作区、收件箱（客服会话/工单/内部聊天/商务沟通）、联系人、报表（7 大视图）、工作区设置与个人设置 |
| 管理员端（`apps/admin`） | `/admin/` | 平台管理员 | 全局概览、工作区生命周期管理、成员账号启停与重置、模型网关与预算配额、功能开关灰度、邮件与常规设置、系统自检、队列与定时任务调度、平台操作审计 |
| 网页聊天插件（`apps/widget`） | `/widget/`、`/loader.js` | 客户 / 商务联系人 | 嵌入产品网站与 App WebView 的实时聊天窗（支持电脑、手机与 WebView），以及成员个人商务沟通链接 `/c/{code}` 聊天页 |

### 双套认证与令牌体系

- **平台管理员**（`__Host-admin` cookie）与**工作区成员**（`__Host-session` cookie）相互隔离，工作区成员账号全局唯一并可隶属多个工作区，在各工作区内拥有独立角色与权限。
- 管理员端与工作区端均支持签发与吊销 API 令牌（含**只读令牌**选项），所有接口均可使用 `Authorization: Bearer` 调用。
- 客户通过网页聊天插件使用隔离的联系人令牌（`contactTokens`），仅可访问和发送本人所在插件及渠道下的连续对话与工单进度。
- 登录、忘记密码与重置密码接口按客户端 IP 施加防暴力破解限流；邮件验证码与邀请链接由 Resend 动态邮件服务发送。

## 2. 账号、工作区、角色与组织架构

### 2.1 工作区与主管理员

- **工作区（Tenant）**：业务隔离的基本单位，每个工作区拥有独立的 `id`（UUIDv7）与地址 `slug`（`/t/{slug}/`），支持设定工作区名称、Logo 与对话关闭后**重开窗口（默认 24 小时）**。
- **主管理员**：每个工作区指定一位主管理员（拥有全部工作区权限），可由平台管理员创建或更换。
- **工作区停用**：平台管理员停用工作区后，工作区成员无法进入，历史数据完整保留。

### 2.2 角色与权限

- 成员在工作区内绑定一个管理员维护的角色，权限由以下两部分构成：
  - **会话可见范围**（三选一）：全部会话（`all`）、所在团队收件箱与指派给自己的会话（`team`）、仅指派给自己的会话（`assigned`）。
  - **操作权限**：覆盖改派会话（`conversations:assign`）、回复与处理会话（`conversations:reply`）、管理团队收件箱、管理成员和角色、管理工作区公共渠道、管理个人/工作区商务渠道、管理快捷回复、管理共享视图、查看报表、导出联系人、管理标签与属性、管理工单类型、管理工作区常规设置等细粒度权限。
- 内置初始角色包含“管理员”和“坐席”；主管理员支持变更角色但不允许删除仍在使用中的角色（并发安全锁保护）。

### 2.3 团队收件箱、工作时间与在线状态

- **团队收件箱（Team Inbox）**：共同承接服务型会话的服务队列（如“一线客服”“IT 服务台”），支持两种分配方式：
  - **手动（`manual`）**：新会话进入队列，由有权限的成员领取或由管理者指派；
  - **轮流（`round_robin`）**：按成员顺序依次分给在线成员。
- 团队收件箱支持独立设置时区与工作时间，有在途会话或渠道引用时可停用（停止接单但保留历史与报表展示），空团队可删除。
- **工作时间**：工作区可配置默认时区、每周排班时段、特殊节假日/调休日期以及参考回复时间（如“几分钟内”），换算“等待处理”和“需要注意”的超时提醒阈值；团队收件箱可覆盖配置自身时区与班次。
- **成员在线状态与工作交接**：成员状态分为“在线”与“离开”；系统心跳检测超过 5 分钟无响应时自动转为离开状态。设为离开时可勾选将本人尚未关闭的会话重新分配回团队收件箱；成员离职或转岗前管理员可使用**工作交接（Handover）**，将名下在途服务型会话与工单批量移交指定成员、团队收件箱或退回队列。

### 2.4 联系人与客户组织

- **联系人分类**：
  - **用户（`user`）**：由接入方服务端经 HMAC 签名验证后传入真实身份的客户；
  - **线索（`lead`）**：通过网页聊天插件首次打开窗口或发消息建立的匿名访客，以浏览器持久化访客编号识别，可随时留资并在线索登录验证后自动合并为对应用户；
  - **内部联系人（`internal`）**：通过内部服务渠道发起 1:1 对话的企业内部员工，可关联到工作区成员并在联系人模块中独立分组展示。
- **客户组织（`organizations`）**：支持创建、编辑、删除客户组织（名称、工作区内唯一外部编号 `external_id` 与自定义属性），用于归属往来公司级别的联系人和外部群。
- **联系人生命周期与合规治理**：
  - 支持多渠道身份绑定（1 个联系人对应多个渠道账号）；
  - **联系人合并**：合并两个联系人时在事务内同时合并其渠道身份、工单关联与活跃服务型会话，保持“一客一活跃会话”不变量；
  - **拉黑与匿名化**：支持拉黑/解除拉黑联系人，拒收后续来信；支持对联系人执行不可逆**匿名化清理**以响应数据清理要求；
  - **保存视图与异步导出**：支持保存联系人自定义筛选视图，并在后台生成表格异步导出通知下载。

### 2.5 标签与自定义属性

- **标签**：可应用于会话和联系人，支持自定义颜色与筛选统计，加/去标签写入会话时间线系统事件。
- **自定义属性**：支持文本、数字、日期、布尔值、单选与多选六种类型，分别作用域于联系人、会话、工单（可按工单类型隔离）与组织，修改属性写入时间线系统事件。

## 3. 全渠道接入与媒体治理

渠道按**传输协议**（连接器种类）与**服务对象域**（`customer` 外部客户、`partner` 商务伙伴、`internal` 内部员工）正交建模，并按归属分为**工作区公共服务渠道**与**成员个人商务渠道**，支持启用、停用与归档。

### 3.1 已实现渠道一览

| 渠道类型 | 归属 | 传输机制 | 主要特性与约束 |
|---|---|---|---|
| **网页聊天插件**（`widget`） | 公共服务渠道 | 浏览器实时频道 + HTTP API | 电脑/手机浏览器 iframe 与 App WebView 接入；按站点配置动态生成 CSP `frame-ancestors`；HMAC 用户身份签名校验与密钥轮换；懒建线索；连续对话流（旧轮次分隔线 + 1–5 星评价 + 客户工单入口）；`widget.visitor_uploads` 灰度控制；支持配置渠道专属 IP 黑名单网关拦截 |
| **Telegram 机器人**（`telegram`） | 公共服务渠道 | HTTP Webhook + Secret Token | 支持 `customer`/`partner`/`internal` 三类服务对象；支持私聊与外部群 `@` / 命令触发；支持引用回复与外部发言人 `@提及`；高可靠按需媒体文件下载 |
| **企业微信智能机器人**（`wecom`） | 公共服务渠道 | WebSocket 长连接（`aibot_subscribe`） | 支持单聊与群聊 `@`；支持基于 `req_id` 的被动流式/快捷回复及超时降级主动推送（`aibot_send_msg`）；支持流式加密媒体解密与本地化转存；内置基于 PostgreSQL 分布式锁与 NATS RPC 的多实例租约选主与出站转发机制，消除多副本互踢 |
| **商务沟通链接**（`business_link`） | 个人商务渠道 | 浏览器实时频道（复用聊天窗） | 成员个人可创建多个专属 `/c/{code}` 短链，配置名称、问候语与主题色，支持预览与启停；支持协作者管理与管理员商务策略/配额管控 |
| **Telegram 个人号**（`telegram_account`） | 个人商务渠道 | 纯 Go MTProto 长连接 | 由平台配置 Telegram API 凭据，成员个人通过扫码或手机号 + 二步验证接入；加密保存会话状态；支持多实例租约防冲突与 NATS RPC 出站发送；按白名单精确双向同步选定单聊与群聊并可导入近期历史消息；商务聊天中支持内部备注且不外泄 |
| **内置测试渠道**（`test`） | 公共服务渠道 | 进程内模拟连接器 | 配合种子数据与 `dev message` 命令行工具完成收发、翻译、自动分配与 AI 接待闭环验证 |

### 3.2 外部群路由与 AI 自动接待配置

- 机器人接入第三方群聊后，日常群内闲聊不会导入收件箱，仅群内 `@ 机器人`、机器人指令与直接回复机器人的消息进入当前群对应服务型会话。
- 首次接入的新群自动标记为 **待设置（`pending_setup`）**，坐席仍可在收件箱正常回复防止漏接；管理员可为其配置默认团队收件箱、关联客户组织（仅商务群），或解除启用 AI 自动接待。
- 公共服务渠道的 `settings.ai_reception` 支持配置是否启用进线 AI 自动接待（`enabled`）、绑定的机器人（`bot_id`）及初始接待控制模式（`ai_auto` 或 `ai_copilot`）。

### 3.3 附件、图片与媒体存储生命周期

- **安全隔离存储**：会话与工单附件使用私有存储（Private Disk）隔离，下载经权限与令牌校验，禁止直接公开暴露。
- **安全拦截**：上传写入临时区域，正式发出前严格校验文件真实 MIME 类型与大小上限，拦截可执行脚本（HTML、SVG 脚本、ActiveX 等）及伪装扩展名。
- **缩略图与冷热治理**：图片支持经由 imgproxy 按需生成签名缩略图；外部渠道拉取失败或中断的媒体由定时任务 `media:recover-fetching` 自动重置重试；超过 30 天的冷视频本地缓存由 `media:evict-cache` 自动回收（保留封面与远端引用，支持坐席按需重新拉取）。

## 4. 统一会话内核（服务型会话、工单、聊天型会话）

系统所有对话复用统一内核表结构，所有写操作经统一业务动作与事务（Outbox + 实时推送）提交。

### 4.1 时间线不变量

- 时间线仅追加写入（`timeline_items`），每条包含会话内自增序号 `seq`、发起者类型（`contact` / `external_user` / `member` / `bot` / `system`）与 ID、内容种类（消息 `message` / 内部备注 `note` / 系统事件 `event`）、可见范围（所有人 `all` / 仅成员 `members`）、来源/目标渠道、文本与附件、派生译文、逻辑排序锚点 `after_seq` 与 AI 生成关联 `generation_id`。
- **编辑、撤回与更正**：
  - **编辑（`message_revisions`）**：保留完整修改历史版本，同时触发翻译索引增量更新；
  - **撤回（`message_recalls`）**：在时间线、预览缓存与未读提醒中同步隐藏撤回内容，消除历史通知或列表摘要泄漏；
  - **更正（`message_corrections`）**：成员与客户消息支持引用原文发送带标注的更正消息。
- **送达状态追踪**：外发消息独立维护送达状态（发送中 `sending` / 已送达 `delivered` / 已读 `read` / 失败 `failed`），失败消息支持重试投递。

### 4.2 服务型会话（`kind = service`）

- **单活跃会话不变量**：通过数据库部分唯一索引强制保障“同一联系人在工作区同一服务对象域内最多存在一条未关闭（`open` / `snoozed`）的服务型会话”，消除多端重复建单与上下文割裂。认证客户从多渠道来信自动归入活跃会话，时间线标注各消息所在渠道，坐席可在回复框直接切换发往渠道。
- **状态与服务轮次**：支持 `open`（打开）、`snoozed`（稍后处理，到期由 `conversations:unsnooze` 唤醒或客户回复立即唤醒）、`closed`（已关闭，支持配置小时级重开窗口）。每次打开至关闭计为一个服务轮次（`conversation_rounds`），精确记录本轮首次回复时长、总解决时长、客户满意度评分（1–5 星）、AI 生成次数（`ai_generation_count`）、转人工原因（`handover_reason`）与解决归因类型（`ai_resolved` / `ai_assisted` / `human_resolved`）。
- **运营治理**：支持垃圾会话标记与移出（自动关闭且不计入常规收件箱与统计）、同工作区历史会话合并（事务内原子合并时间线、`agent_turns` 与关联数据并取消源会话活跃 AI 生成）、服务型会话异步导出、基于工作区配置的闲置自动关闭（`conversations:auto-close`）与轮流团队超时未回复 SLA 自动改派（`conversations:sla-reassign`）。

### 4.3 工单（`kind = ticket`）

- 工单直接作为第三类会话复用时间线、指派、跨语言翻译、搜索和推送能力，工单专有字段存放在扩展表与多对多联系人关联表（`ticket_contacts`）中，工作区内配严格递增工单编号（如 `#1001`）。
- **工单类型（`ticket_types`）**：可选，管理员维护各类型的名称、默认团队收件箱、默认可见范围、排序及专属自定义字段（`target = ticket`）；成员建单时也可选择暂不关联类型，随时补充或切换。
- **可见范围与 4 大状态**：支持客户可见（`all`）与仅成员可见（`members`），固定流转 `submitted`（已提交）→ `in_progress`（处理中）→ `waiting_on_customer`（等待客户）→ `resolved`（已解决，支持重开）。
- **跨客户协同闭环**：支持从多条服务型会话批量转入同一工单或把联系人加入已有工单；`members` 内部讨论按成员语言互译；`all` 工单发布公开进度后，队列任务按所有受影响客户的语言去重翻译并分别送达其当前活跃服务型会话；当处于“等待客户”的工单下任一关联客户发来新消息时，工单自动回流至“处理中”。

### 4.4 聊天型会话（`kind = chat`）

- 分为**工作区内部聊天**（支持成员间唯一单聊、**成员与已启用 AI 机器人的单聊**、群聊）和**商务沟通聊天**（绑定成员个人商务沟通链接或 Telegram 个人号）。
- 成员关系按有效期区间（`chat_membership_intervals`）存储，支持群成员拉入、移出、退群改名，并保证离开成员仅能阅读其所在时段消息。
- 支持未读数、已读游标、`@ 成员` 提醒；商务聊天内支持撰写仅协作成员可见的内部备注。

## 5. 跨语言双向翻译

系统面向多语言团队设计，支持按成员与客户各自母语无感沟通：

- **语言与书写方式识别**：入站消息经模型自动识别语言与书写系统（例如使用拉丁字母拼写的印地语 `hi-Latn` 等）；短确认词、纯数字、链接等标为“未确定（`und`）”，不干扰客户主要语言判断。
- **客户语言推导与手工锁定**：自动根据客户最近三条确定语言的来信中出现频次最高者推导客户语言；成员也可在会话详情中手动覆盖锁定，或随时切回自动识别。
- **入站预译与按需补译**：新来信自动翻译为工作区主要语言（当前有效成员使用人数最多的语言），不同语种成员查看会话、工单或聊天时后台按成员个人语言去重补译并实时推送；内部备注与内部聊天自动按读者语言互译。
- **出站双发机制（自动翻译 / 译文校对）**：
  - **自动翻译直发**：成员直接用自己的母语回复，消息立即可见（附“翻译并发送中”提示），后台队列译为客户语言后发往外部渠道；若后台翻译失败（含模型不可用、预算熔断或输出异常），系统严禁发送原始未翻译文本并保持发送失败态以便重试；
  - **译文校对**：按需展开“左原文 | 右译文 + 盲回译核对”对照栏，支持临时调整目标语言与此次回复语气、手动精修译文并确认发出；同时支持单次选择“按原文发送”。
- **工作区翻译规范**：支持设置默认语气（亲切 / 中性 / 正式）与工作区术语表（品牌词保持原样或设定各语种固定译法）；模型网关识别/翻译请求默认关闭深度推理以获得低延迟与低成本。

## 6. 自动指派与内置自动化

### 6.1 自动指派规则

- 工作区可设置新会话默认进入的团队收件箱或直接指派的默认成员（渠道及外部群配置优先于工作区默认配置）。
- 支持**成员回复即领取**（回复未指派、仅指派到团队收件箱、或当前由 AI 机器人负责的同团队会话时，会话自动指派给介入坐席），并发领取通过数据库行锁保证先到者生效。
- 成员无 `conversations:assign` 权限时仍可将属于自身团队收件箱的机器人（`BotActor`）会话领取为自己负责。

### 6.2 内置自动化引擎

- 数据层由声明式规则表（`automation_rules`）、执行审计表（`automation_runs`）及幂等去重键 `(rule_id, dedup_key)` 驱动，按功能开关 `conversation.auto_automation` 灰度控制。
- 当前默认内置 4 条管理员可独立开关的业务规则：
  1. `reply_time`：客户首条消息进线时，按当前是否处于工作时间发送预期回复时间提示；
  2. `collect_lead_contact`：匿名线索首次咨询时发出结构化留资引导提示；
  3. `request_rating`：服务型会话关闭后邀请客户评价（1–5 星）；
  4. `ticket_status_notify`：客户可见工单状态变更时自动同步状态通知至相关客户当前活跃会话。

## 7. AI 底座、模型网关与 Agent 运行时

系统已完成底层 AI 运行时、会话控制状态机与安全隔离建设，具备直接接入与迭代上层 AI 业务能力的全部底座：

### 7.1 统一模型网关与配额审计（`internal/llm`）

- 平台设置统一配置单一 OpenAI 兼容模型网关地址与加密密钥，以及 6 类调用槽位逻辑模型名：`chat`（对话与推理）、`fast_router`（路由分类）、`translation`（翻译与语言识别）、`embedding`（向量化）、`rerank`（检索重排）、`transcribe`（语音转写）。
- **多租户预算熔断**：支持全局默认工作区预算及单工作区覆写配额（每日费用 USD、每月费用 USD、每日总 Token 上限）；网关客户端通过统一 `RoundTripper` 注入会话粘性头（`X-Omirouter-Session`）、AI 生成 ID 与业务归因、记录每笔调用的输入/缓存/输出/思考 Token 与美元费用至 `llm_calls`，并在达到配额上限时返回 `llm.budget_exceeded` 实时熔断。

### 7.2 机器人一等公民与控制权状态机

- **机器人（`bots`）管理**：提供工作区级 `GET/POST /bots` 与 `PUT/DELETE /bots/{id}` 接口，维护启用状态、模型覆写、系统提示词、提示词版本、允许工具白名单、审批工具清单、防抖窗口（`debounce_ms`）、最大工具步数、插话策略（`notify` / `cancel_restart`）。删除仍被活跃会话、渠道自动接待或进行中生成占用的机器人时返回 `agent.bot_in_use` 拒绝删除。
- **一等指派与聊天参与**：`ActorType = bot` 可作为服务型会话负责人、内部单聊对话方与消息作者；支持按 `assignee_type=bot` 与 `handling_mode` 在列表、搜索、视图及导出中筛选。
- **显式接待控制权状态机（`conversations.handling_mode`）**：

| 模式 | 含义与流转规则 |
|---|---|
| `human` | 人工接待模式，AI 不自动发言 |
| `ai_auto` | AI 自动接待，由启用的机器人直接流式生成并写入时间线发给客户；支持经入站路由（`InboundRouter`）按渠道 `ai_reception` 自动进入 |
| `ai_copilot` | AI 副驾驶模式，后台为客户新消息生成 `draft` 模式草稿，不自动发往客户；坐席在界面可一键采纳进回复框并携带 `source_generation_id` 定稿发送 |
| `ai_paused` | 人工接管或异常降级后暂停 AI 自动触发（人工发送回复、AI 主动调用转人工工具 `handover_to_human`、预算熔断 `budget_exceeded` 时自动转入并取消活跃生成） |
| `waiting_approval` | AI 调用高风险工具触发人工确认，生成暂挂等待成员审批，审批全部决断后自动恢复至原先 AI 模式续跑 |

- 成员拥有回复权限时可在会话中随时通过接口 `PUT /conversations/{id}/handling-mode` 或前端操作按钮切换人工接管、恢复 AI 自动接待或切换 Copilot 副驾驶模式。

### 7.3 统一 Agent 运行时（基于 `tenon/ai/chat`）

- `internal/agent` 由工作区全局托管实例 `agent.Service` 驱动 `tenon/ai/chat.Runs`（启用 `UseHistory`、`AgentFor`、`RequireApprovalOf` 与多实例 `Cluster` 协作，并由进程生命周期 `stack.MustAdd("ai", agentSvc.Shutdown)` 实现优雅排空）：
  - **上下文存储与断点审批恢复**：`historyStore` 将时间线消息与数据库表 `agent_turns`（保存 `tool_calls` 与 `model.RoleTool` 结果）按逻辑锚点 `after_seq` 交错排序，保证高风险工具暂停审批后从断点原样继续对话；
  - **严密隔离防泄漏**：对面向外部客户的 `ai_auto` 对话，历史加载层从数据库查询严格限定仅可见 `kind = 'message' AND visibility = 'all'`，内部备注及仅成员可见内容绝对不可进入模型上下文；
  - **受信任工具执行与知识检索契约**：所有工具经 `safeTool` 包装并绑定不可由模型传参伪造的 `ExecutionContext`（锁定 `TenantID`、`ConversationID`、`AudienceExternal`、`GenerationID`、`Collector`），内置 `get_conversation_context`、`search_knowledge`（通过可插拔 `agent.Retriever` 接口强限定 `KnowledgeExternal` vs `KnowledgeInternal` 并记录 `citations`）、`handover_to_human`（执行后原子切回 `ai_paused` 并释放 Bot）；工具调用审计日志统一写入 `generations.tool_calls`；
  - **高风险审批流**：标记 `RiskHighImpact` 或命中机器人 `require_approval_tools` 的调用在入库前自动挂起为 `waiting_approval`，成员通过 `POST /generations/{id}/approvals/{call_id}/approve` 或 `.../reject` 批准备案或退回原因给模型续写；
  - **多语言同步合约**：`BuildInstruction` 自动绑定目标客户 BCP 47 语言（含书写方式变体如 `hi-Latn`）、工作区翻译语气、术语表约束及防外泄护栏；
  - **高并发防线**：数据库唯一部分索引（`generations_one_active_per_conversation`）保障同一会话同一时刻最多存在 1 条活跃生成；内置按序号让位的消息防抖（`DebounceMS`）与双模客户插话策略（`notify` 续写 / `cancel_restart` 取消重跑）；后台定时任务 `generations:expire` 每分钟兜底回收超期僵死生成。

### 7.4 工作区 AI 中心入口（功能开关控制）

- 工作区包含 `/$slug/ai` 入口概览页，受平台功能开关 `ai.workspace`（默认关闭）控制，展示各服务对象（对外客服、内部服务、商务沟通）渠道接入概况与配置状态。

- **总览与工作区治理**：平台运行统计总览、工作区创建/编辑/停用/主管理员更换，支持填报原因并留存审计轨迹的管理员**代为登录（Impersonation）**排障入口。

- **单一部署与多实例水平扩展**：所有前端资源经 `go:embed` 打包进主二进制；生产推荐以原生二进制 + `systemd` 零停机重启部署；PostgreSQL 分布式锁与 NATS 广播/JetStream 保证 HTTP 与 Worker 实例可任意横向扩缩，长连接渠道（企微、Telegram 个人号）与 AI 运行自动协调归属不重复执行。
- **事务一致性**：每次业务变更、时间线写入、操作日志记录与后台异步任务（Outbox 模式）在同一个 PostgreSQL 事务中原子提交；广播推送与进程内运行取消挂载在 `tx.AfterCommit` 上执行，杜绝脏推与幻读。
- **前后端契约一致**：Go 业务结构体与枚举注释经 OpenAPI 规范自动生成强类型 TypeScript 客户端（`packages/client`）与多语言键表，静态检查 CI 强制拦截未生成代码、硬编码界面文字及越界主题色。
