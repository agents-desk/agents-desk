## 两端和账号

### 三个前端

| 前端 | 路径 | 谁用 | 做什么 |
|---|---|---|---|
| 管理员端 `apps/admin` | `/admin` | 平台管理员，负责整套部署 | 创建和停用工作区，指定主管理员；平台设置：各用途的模型接口（地址、密钥、模型名）、邮件发送、文件存储；系统状态（任务队列、版本）；平台管理员账号；平台操作日志 |
| 工作区端 `apps/web` | `/` | 工作区的成员：坐席、组长、工作区管理员、主管理员 | 工作台、会话、工单、联系人；工作区设置：成员、团队、角色、工作时间、SLA、网页插件、工单类型、术语表；个人设置：工作语言 |
| 网页插件 `apps/widget` | `/widget` | 客户 | 在官网的聊天窗口里咨询 |

### 账号

- 平台管理员和工作区成员是两套账号，登录入口和会话 cookie 分开。同一个人可以同时拥有两种账号。
- 权限按域分配：平台是一个域，每个工作区各是一个域。
- 工作区成员的账号全局唯一：一个人登录一次，可以属于多个工作区，在工作区之间切换。
- 工作区角色：主管理员、管理员、组长、坐席。

### 第一个平台管理员

用命令创建：

```bash
agents-desk admin create --email ops@example.com
# 交互式输入密码；用 Docker 部署时：docker compose run --rm app admin create --email ops@example.com
```

之后平台管理员登录管理员端，创建工作区并指定主管理员；主管理员登录工作区端，添加成员。

## PR 列表

### PR 1：地基和管理员端

**目标：** 平台管理员能登录管理员端，创建工作区并指定主管理员。

- 移除 todo 示例；接入 PostgreSQL、迁移和 NATS。
- 平台管理员账号、登录、`admin create` 命令。
- 管理员端：工作区列表、创建、停用；指定或更换主管理员（同时创建主管理员的成员账号）。
- 平台设置页：每种用途一个模型接口（地址、密钥、模型名），不同用途可以使用不同的接口。密钥明文保存。
- 建立 `docs/adr`，写第一篇 ADR：内核概念和统一写入路径。

**完成标准：** 用命令创建平台管理员，登录管理员端，创建一个工作区并指定主管理员；主管理员的账号已创建。

### PR 2：成员登录工作区端

**目标：** 成员能登录工作区端，进入和切换自己所属的工作区。

- 成员的登录、退出和当前账号（`/api`），会话 cookie 是 `__Host-session`，与管理员端分开。
- 工作区的接口在 `/t/{slug}/api` 下：租户中间件按 slug 查出工作区，业务代码只见到 ID。不是成员（包括 slug 不存在）时 404，工作区停用时 403。
- 登录后的去处：只属于一个工作区时直接进入，属于多个时选择，一个都没有时提示联系管理员。
- 工作区端的应用框架：侧边栏（工作台、会话、设置，都是占位页）、个人菜单（切换工作区、退出）。

**完成标准：** 主管理员用自己的账号登录工作区端，进入工作区，看到侧边栏；打开停用的工作区看到“已停用”，打开别人的工作区看到 404。

### PR 3：个人资料

**目标：** 平台管理员和工作区成员都能修改自己的名字、头像和密码。

- 文件存储：接入 Tenon 的 `filesystem`，默认是本地目录（`storage/files`，在 `/storage/` 下提供访问），也可以配置 S3；上传接口 `POST /files`，没有用上的临时文件由定时任务回收。
- 个人资料（两端都有，从头像菜单进入）：名字、头像（PNG、JPEG、WebP，不超过 2 MB），换头像时删除原来的文件。
- 修改密码：校验当前密码，改完后其他登录失效，这次登录保留。

**完成标准：** 两端各自上传头像、改名、改密码；头像菜单中显示新头像；改密码后其他设备上的登录退出。

### PR 4：偏好设置

**目标：** 成员按自己的语言和时区工作。

- 框架：显示时间时可以指定时区（`useFormatDateTime`、表格、操作记录等），发版后升级。
- 工作区端的偏好设置（设置的“个人”一节）：语言，现在决定翻译的目标语言，以后有了多语言界面时也决定界面语言；时区，默认跟随浏览器。

**完成标准：** 成员选了时区后，页面中的时间按这个时区显示；语言保存下来，双向翻译时使用。

### PR 5：角色和成员管理

**目标：** 工作区的管理员能添加成员、分配角色。

- 角色和权限：主管理员、管理员、组长、坐席，每人在一个工作区中一个角色；主管理员不再是 `*`，改为明确的权限列表。
- 成员管理：管理员添加成员（新账号设置初始密码，已有账号直接加入），修改角色，把成员移出工作区（撤销角色，账号和记录保留）。主管理员只在管理员端更换；任何人不能修改、移出自己。
- 工作区的常规设置：修改名称。
- 菜单和按钮按角色显示：坐席和组长的设置中只有“个人”一节。

**完成标准：** 主管理员添加一个坐席；坐席用自己的账号登录，看到按角色显示的菜单。

### PR 6：团队

**目标：** 成员按团队组织，为分配工单做准备。

- 团队：主管理员和管理员新建、修改、删除团队；从工作区的成员中加人、移出，指定组长。一个人可以在多个团队中，一个团队可以有多个组长。
- 只有组长、管理员和主管理员能当团队的组长；成员的角色改为坐席时撤掉他的组长身份，被移出工作区时也移出这个工作区的团队。
- “我的团队”：每个成员都能看到自己所在的团队和其中的组长、成员。
- 顺带：成员列表中主管理员和自己那一行不显示“修改”“移出”（Tenon v0.0.10 的 UpdateWhen）。

**完成标准：** 主管理员创建团队、指定组长、加入坐席；组长在“我的团队”中看到自己的团队。

### PR 7：内核写入路径

**目标：** 落地“统一写入路径”和“统一判定入口”。

- 参与者统一编号：成员、团队、联系人、系统。联系人可以有多个外部身份，由“连接器 + 外部编号”确定。
- 房间和房间成员，成员分内部方和外部方。
- 事件只追加：房间内递增的序号、发起者、类型、可见范围（所有人 / 仅内部）、内容、外部编号、派生内容。
- 写入路径：动作 → 判定（这一阶段是角色权限规则）→ 一个事务里写业务表、事件和任务 → 提交后分发。
- 实时推送：每个房间一个频道，每个成员一个个人频道。
- 每个动作写入操作日志。

**完成标准：** 测试覆盖：动作在一个事务中写入；判定拒绝时数据保持原样；同一个外部编号重复投递只生效一次；提交后客户端收到实时推送。

### PR 8：网页插件和客户会话

**目标：** 官网上的客户能发消息，坐席实时看到并回复。

- 连接器接口：收消息、发消息、能力声明、回执。网页插件是第一个实现。
- 插件设置（工作区设置中）：名称、颜色、默认团队、签名密钥、嵌入代码。
- 访客识别：浏览器中保存的访客编号；客户在官网登录后，官网后端用插件的签名密钥签发短期令牌，客户成为已验证的联系人。
- 客户第一次发消息时创建联系人和客户会话，记录来源（页面、来源网址、广告参数）。
- 消息状态：发送中、已送达、已读。
- 插件前端：一段脚本在官网右下角放一个按钮，点开后是 iframe 中的聊天窗口。
- 坐席端：会话列表和会话页，回复和内部备注。

**完成标准：** 在测试网页上嵌入插件，客户发消息，坐席实时收到并回复；客户刷新页面后看到完整历史。

### PR 9：工单和工作台

**目标：** 每个咨询形成工单，有人负责到底。

- 工作项，这一阶段只有工单一种类型。字段：编号、标题、类型、请求人、团队、负责人、状态、优先级、SLA 期限、自定义字段。
- 消息归入：会话中有进行中的工单就归入它；会话中的工单都已关闭时新建工单。坐席可以合并、拆分工单，或把消息移到另一张工单。
- 状态和流转：新建、处理中、待回复、挂起、已解决、已关闭（规则见 README 3.3）。
- 分配：领取、指派、转接；同时领取时先到者生效。
- SLA 和自动关闭：按团队的工作时间和时区计算，用任务队列的定时投递处理到期提醒、退回队列和自动关闭。
- 工单类型和自定义字段的管理；团队的工作时间和 SLA 设置。
- 工作台：我的工单、待领取、@我；工单详情的右侧栏。

**完成标准：** 客户发消息 → 新建工单进入队列 → 坐席领取并回复 → 标记已解决 → 48 小时后自动关闭；客户就同一件事再来时，新建工单并关联原工单。

### PR 10：双向翻译

**目标：** 坐席用中文和说 Hinglish 的客户顺畅沟通。

- 模型调用：使用平台设置中的接口和模型名，每次调用带业务标签，记录接口返回的用量和费用。
- 客户的每条消息在后台识别语言和书写方式（天城文、拉丁字母的 Hinglish），译成坐席的工作语言，识别和翻译在同一次模型调用中完成，存为派生内容；翻译失败时消息照常显示，稍后重试补上译文。
- 回复前的译文预览：返回目标语言的译文和译回中文的结果；发送时保存中文原文和发给客户的译文。
- 术语表：固定译法；订单号、金额、链接保持原样。
- 记录“看到回译后修改原文”的次数，用于翻译修改率。
- 前端：会话页切换原文和译文；回复框下方的译文预览和回译；术语表管理页。译文的语言取偏好设置中的语言（PR 4）。

**完成标准：** 客户发英语、印地语、Hinglish，坐席看到中文；坐席的中文回复按客户使用的语言和书写方式发出。

## 已确定的决定

| 问题 | 决定 |
|---|---|
| 平台管理员和工作区成员是否分两套账号 | 分两套，登录入口和会话 cookie 分开 |
| 工作区成员的账号范围 | 全局账号，一个人可以属于多个工作区 |
| 模型接口在哪一层配置 | 平台层统一配置，每种用途一个接口和模型名；以后按需允许工作区覆盖 |
| 成员账号的创建方式 | 管理员创建账号并设置初始密码；邀请邮件放到后面 |
| 不再需要一个成员时 | 移出工作区：撤销他在这个工作区的角色，账号和他留下的记录都保留，可以再加回来；暂不提供只停用不移出 |
| 管理员能否管理其他管理员 | 能：管理员可以添加、修改、移出其他管理员，不能动主管理员和自己 |
| 团队的组长 | 一个团队可以有多个组长；只有组长、管理员和主管理员能当，角色改为坐席时撤掉组长身份 |
| 组长能否管理自己团队的成员 | 暂时不能，团队由主管理员和管理员管理 |
| 官网传递客户身份的方式 | 官网后端用插件的签名密钥签发短期令牌（JWT） |
| 译文的存储 | 存在事件的派生内容中，按语言区分 |
| 插件的嵌入方式 | 一段脚本加 iframe |
| 工作区在代码中的名字 | 统一叫 tenant（表 `tenants`、列 `tenant_id`、包 `internal/tenant`），与 Tenon 的租户一致；给用户看的文字叫工作区，见 [ADR 0002](adr/0002-账号、租户与权限的域.md) |
| 工作区的标识和地址 | ID 是 UUID，作为租户、权限的域和 `tenant_id`；地址是 slug（`/t/{slug}/`），创建后不能修改。以后的自定义域名也只是地址 |
| 更换主管理员 | 撤销原主管理员的 owner 角色；他在这个工作区中没有其他角色时，也就不再是成员 |
| 语言识别 | 与翻译在同一次模型调用中完成，不单独配置模型接口；坐席回复的目标语言取客户最近一条消息识别出的语言和书写方式 |
| 管理员端的接口 | `/admin/api`，只接受平台管理员，会话 cookie 是 `__Host-admin` |
